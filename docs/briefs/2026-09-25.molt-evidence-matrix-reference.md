## The three inputs

The new molt reads up to three inputs.
The artifact's own prose is always present.
The two evidence corpora are optional, and each answers a different question: the harness corpus says what the harness already tells the model, and the model notes say how the target model responds to prose.

| Input          | Presence | Source                                                                                       | Perspective           | Used for                                    | If absent          |
|----------------|----------|----------------------------------------------------------------------------------------------|-----------------------|---------------------------------------------|--------------------|
| Artifact prose | Always   | The file under audit                                                                         | Its own text          | Every step; D4 and the mechanical D5 checks | No audit           |
| Harness corpus | Optional | qmd collection, or grep on a folder-of-.md checkout (e.g. `~/repos/claude-code-system-prompts`) | What the harness says | Plumbing, D1, harness premises              | Memory, unverified |
| Model notes    | Optional | Anthropic's per-model prompting pages, downloaded at molt time to `model-notes/<model>.md`, optionally qmd-indexed | How the model reacts  | Choreography, D2, D3, D5                    | Memory, unverified |

The split follows molt's bins.
Plumbing ("mechanics the harness now performs unprompted", `protocol.md:46`) is judged against the harness corpus.
Choreography ("step-by-step behavior a frontier model does by judgment", `protocol.md:49`) is judged against the model notes.
The subtraction test is the final verdict either way: it runs a real task and uses neither corpus.

## Which inputs each finding class needs

| Finding class                              | Artifact | Harness | Model notes |
|--------------------------------------------|----------|---------|-------------|
| Plumbing: the harness already does it      | yes      | yes     | -           |
| Choreography: the model does it unprompted | yes      | -       | yes         |
| Duplicates or conflicts with the harness   | yes      | yes     | -           |
| Contradiction inside the artifact          | yes      | -       | -           |
| Wording fails the standard                 | yes      | -       | yes         |
| Addition for a documented model need       | yes      | -       | yes         |
| Stale premise about the harness            | yes      | yes     | -           |

Notes:
- Contradictions inside the artifact need only the artifact, so D4 is the one new check that works with neither optional input.
- Wording draws on two sources: the model notes supply the dated patterns, and the owner's banned-token list enters through the constraint register (jrit-core's `ci/banned-tokens.txt` can supply it as data).
- When an input is missing, molt falls back to memory, marks the verdicts that depend on it as unverified, and the ledger records which inputs were present.
- Jev is not a third input; it is an optional accelerator over the comparisons, shown in the next matrix.

## The Jev overlay: where Jev runs in the shadow pilot

The same finding-class matrix, with a column showing what Jev does in the shadow version.
The pattern everywhere Jev applies: qmd narrows candidates, Jev picks match-or-none per pair, and a frontier model writes the findings (Jev returns only a pick and a confidence).
A frontier-only pass runs alongside, and the pilot compares what each flags.

| Finding class                              | Artifact | Harness | Model notes | Jev in the shadow pilot                                                    |
|--------------------------------------------|----------|---------|-------------|-----------------------------------------------------------------------------|
| Plumbing: the harness already does it      | yes      | yes     | -           | Stage 1: qmd narrows the corpus (thousands of fragments) to ~10 candidates per block; Jev picks the match or "none" |
| Duplicates or conflicts with the harness   | yes      | yes     | -           | Same two-stage check as plumbing; a "match" here is a duplication or collision finding |
| Contradiction inside the artifact          | yes      | -       | -           | Stack-wide sweeps only (a single artifact fits one frontier pass): Jev judges rule pairs after a qmd similarity filter, tuned to over-report, frontier model rejects the extras |
| Choreography: the model does it unprompted | yes      | -       | yes         | No Jev; the subtraction test is the verdict                                 |
| Wording fails the standard                 | yes      | -       | yes         | No Jev; grep covers banned tokens, regex covers caps, judgment stays frontier |
| Addition for a documented model need       | yes      | -       | yes         | No Jev; few items, each needs judgment                                      |
| Stale premise about the harness            | yes      | yes     | -           | No Jev; premises verify by a second route, often human research             |

Pilot order and guardrails (from the brief's Jev section):
1. Shadow-mode D1 on one already-molted skill (loop-drive): qmd plus Jev alongside a frontier-only pass; compare flags.
2. If they agree closely and Jev catches something the frontier pass missed, extend to the stack-wide sweep.
3. Then D4, tuned to over-report; never treat Jev's "no" as a clean bill, since indirect contradictions are its documented weak spot.
- Pin one Jev model version at pilot time by checking the live model list on the pilot's access route (owner ruling 2026-09-24); log `r.model` on every call and record it in the D6 evidence fields.
- Calibrate thresholds against the molt ledger's 184 lines of past verdicts before trusting any threshold.
- Jev stays optional, like qmd; molt must still run with neither.

## Why Jev lands where it does

Jev fits a step when it compares the artifact against something large with answers known in advance, high volume, code acting on the result, and a fallback for low confidence (the jev brief's four-part fit test, Appendix B).
Plumbing and harness-conflict checks are list-vs-list against the harness corpus (777 catalog files, roughly 3,800 to 5,100 fragments), so they fit at any audit size.
Pair contradictions explode combinatorially only across many files, so they fit stack-wide sweeps once a similarity filter prunes them; a single artifact fits one frontier pass.
Choreography, additions, and premises are few in number and each needs judgment, which is the jev brief's own "when not to use" (Section 7.7), and the subtraction test is LLM-as-judge, a named anti-pattern (Section 5.2).
